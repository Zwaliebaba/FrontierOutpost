# ADR-016 — A seat is a token, and presenting it is logging in

**Status:** Accepted

**Date:** 2026-09-10
**Decided by:** Owner decision, 2026-09-10.
**Supersedes:** —

---

## Context

The custodian rule enters a player into custodianship after three ticks of absence and lets them
log in and resume; the test plan's primary instrument is the login curve. Both need the server to
know who is present. The one-pager also says nothing carries between matches but rank, which
eventually wants an identity that outlives a match. Phases 0 and 1 of the test plan do not: they
are one match at a time among people recruited by hand.

## Options considered

### A. Accounts from the start

Registration, credentials, recovery, and a season rank tied to an account, before Phase 0. It
front-loads work no phase gates on, and puts a password store in a tree that has no network code
yet.

### B. A token per seat

A match is created with N seats. Each seat has a random token, generated by the server and handed
to a player out of band. Presenting the token is logging in; the server records the time. No
accounts, no passwords, no recovery — a lost token is a seat the match creator reissues.

## Decision

**B.** `FrontierServer.exe` generates a 128-bit token per seat at match creation from the
platform's cryptographic generator (`BCryptGenRandom`, in the SDK), prints them, and stores them in
`Match.bin` (ADR-012). The first message on a connection is `Join(token)`; the server answers with
the seat number or a refusal. Every `Join` is a login event in the event log, and the absence
counter for the custodian rule is ticks since the seat's last `Join` or accepted order.

Rank between matches is out of scope for the loop and is the first thing an account system has to
carry when one exists.

## Consequences

**What this makes easy.** Phase 0 setup is a list of eight tokens in a group chat. The login curve
is a query over the event log.

**What this makes hard.** Nothing persists about a player across matches, so season scoring is a
spreadsheet until accounts exist.

**What it costs.** A token store, and one more record in `Match.bin`.

**What it forecloses.** Nothing; an account is a thing that owns tokens.
